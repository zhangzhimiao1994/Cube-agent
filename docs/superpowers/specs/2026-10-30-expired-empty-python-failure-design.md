# Expired empty native Python failure

## One selected design

Use the existing private PostgresArtifactRepository and one internal Python broker action with inspect/commit phases. Do not implement a second full cache-root archive, new tables/directories/configuration or a model capability. A compact Root retirement fence is required to preserve once independently of DB archives. Old050b lacks persisted native stop evidence and stays retained; Hybrid scope/stage-boundary fixes are excluded.

Candidate evidence: legacy FAILED owner1d3 has no preparation/failed-policy flag; native cache entry contains exactly reservation.json+failed.json, no environment/reference, original TTL expired, existing validators passed (nonzero install exit, no timeout, quiet unit, empty export). Historical marker validity does not establish current quiescence.

## Strict protocol and native proof

`PythonFailedMaintenanceInvocation` is a restricted, noninstalling ProjectInvocation with a fresh `python_release_expired_<uuidhex>` execution identity and timeout<=30s. `PythonFailedMaintenanceRequest` uses action `maintain_expired_python_failure`, phase inspect/commit and, only for commit, the exact inspected `PythonFailedReservationSnapshot`. No host path, deletion key, installation/source execution, approval or grant boolean is accepted. Root independently selects an unambiguous entry matching tenant/run/project/session; it supplies the key and original marker bytes in the snapshot, never trusts caller selection alone.

The snapshot binds schema1, full key, typed scope, origin, exact canonical reservation/outcome UTF8 bytes and their SHA256, plus directory/control stat identities. The root reader requires canonical exact bytes, bounded files, root ownership, private modes, regular nlink1 controls, exact two-member entry, both existing validators and TTL. Both inspect and commit hold native shared admission/cache lock and independently recheck origin project+PythonRoot unit quiet/Job0/cgroup, retained roots and all same-run stages, except the current fresh maintenance stage. No fake environment reference is constructed. Commit reselects and compares the complete snapshot before any mutation.

## Three service phases

1. Existing maintain_capacity bounded scan selects old FAILED owners, including legacy without original preparation/failed-policy flag and historical self_repair source. Under owner row lock: canonical IDs, same stored workspace scope, unchanged terminal version, old enough, all four leases null, no pending approval/undelivered outbox/UNKNOWN or unaccounted continuation authority; invoke inspect only. Historical self_repair keys are not consumers: actual acceptance uses this same RunRow lock and changes status/version/outbox, all rechecked at commit.
2. Release that owner transaction. Put a permanent private Artifact with deterministic UUIDv5 of tenant/run/key/origin/raw hashes; content is deterministic snapshot bytes and identities, without wall time or maintenance invocation IDs. Same ID with different content is an error. Read back exact content/hash/decoded marker bytes. No public event or Run/CP/route mutation. Repository calls cannot occur inside the owner transaction because they independently lock RunRow.
3. Re-lock owner, repeat all predicates and version/scope checks, verify permanent archive through same-session RuntimeArtifactRow hydration (no recursively locking repository call), then invoke commit while holding the row lock. Root freshly checks the snapshot and all native fences. Before removing anything, it O_EXCL-writes, fsyncs and reads back a root0600/nlink1 `retired-<owner-scope-sha256>.json` containing only schema/kind, owner scope, key/origin, marker hashes and deterministic archive ID/hash. No marker bodies are duplicated. Conflicting/partial fences veto. Then FD-unlink the two files and rmdir that exact empty directory, fsyncing its parent. Archive persistence is the trusted service precondition, not a caller-supplied root authority flag. Timeouts or uncertain mutation retain the existing broker UNKNOWN fence. Archive-only success is not capacity success.

The broker has no permanent claim: execution/cancelled IDs are memory-only and successful stages are removed. Therefore `reserve()` must independently reject retired owner scope (tenant/run/project/session, including same key/origin after a broker restart, and changed recipe under that retired owner). A different run does not match. `_catalog/_usage` explicitly validate and count compact fence bytes in original byte/disk quotas; fences are not environment slots and cannot contain trees. Unknown names remain errors. Limits: 1024 retirement controls per cache root, 4096 bytes per control; exhaustion refuses further retirement and never evicts/overwrites old fences. This is once enforcement, not a second archive or an UNKNOWN/STAGED record.

ProviderContinuationRow has no pending/status field. Its existence is historical bytes, not live authority; inspect current checkpoint/route/outbox/lease state that can actually consume a continuation. Missing or unknown settlement remains a veto; a settled retained provider receipt alone is not one.

The new branch uses its own maximum-eight batch/cursor and only persisted generated python_ready (any mode, including actual legacy Hybrid/self_repair) or original Python recipe producers. The original READY query/cursor remains unchanged. Latest checkpoint369's succeeded22/failed1 model history and succeeded35/failed2 tool history is the positive shape; old checkpoint367's prepared call is not substituted. Runtime phase=running with settled ledgers is not itself an active call; prepared/running/UNKNOWN ledger statuses or uncertain markers are vetoes. No historical self_repair/provider row is relabelled or removed.

Only a hash/owner-bound native Crew11/Dispatch CP, directly or inside one bound Hybrid3/Hybrid envelope, can exempt its exact body phase=running. Its models must be a nonempty dict and tools a dict, with every row explicitly succeeded/failed/rejected. No recursive object gets an exemption from a ledger-shaped key; opaque provider phase=running, missing/unknown statuses, foreign child and incompatible runtime layers all refuse. Actual CP369 native layers were separately read by parent; no runtime restore is needed.

## Invariants and verification

Keep eight active entries, original max_bytes, 1GiB reserve and 86400 TTL. No old record/Run state/version/history is modified, no old run or consumed execution is replayed, no operator/manual GC. Only a normal trusted worker maintenance result can report a freed slot.

TDD must cover legacy no-preparation reachability, deterministic permanent archive/exact-byte readback, owner change between phases, archive conflicts/failures, pending consumers, TTL/owner/FD/unit/stage/UNKNOWN/no-env negatives and post-mutation uncertainty. Local mocks do not establish Linux native behavior. Parent gates release on an isolated Linux fixture, then deployed real worker automatic bdb reclamation8->7 and ordinary-user fresh validation.
