## Problem And Boundary

In `src/agent_hub/runtime/crew/adapter.py`,
`_reconcile_structured_handoff_completion` and `_structured_recovery_field_value`
currently manufacture schema fields for invalid fallback/logical-fallback or
project-scale output. Arbitrary text becomes strings/arrays, booleans become
false, and numbers become zero before normal artifact/handoff validation.
`_complete_agent` can also substitute framework `raw` for the last model text.
The independent reviewer exception path in `_execute_step` (investigated at
adapter.py:2852) emits skipped/timeout_skipped with verdict=approve after failed
attempts. Removing this fail-open behavior is mandatory scope, not a follow-up.

Reject this behavior: schema validity must come from an actual model response,
not runtime defaults, a fixture, framework rewriting or fabricated business data.
Retain invalid responses as model evidence, but do not create an accepted business
artifact, complete a contract or run dependent steps until validation succeeds.
Apply one rule to primary/fallback/project-scale and final structured role output.
Preserve valid reviewer approve/revise/reject semantics, but remove exception-based
approval. Do not alter fixture generators, tool permissions, user authorization,
role selection or routing in this slice.

## Strict Validation

Use one strict parser/validator for initial and corrected worker/reviewer output:

- Reject duplicate object keys at every depth with object_pairs_hook; reject
  NaN/Infinity/-Infinity with parse_constant and nonfinite float overflow such as
  1e999 with finite-number validation. Preserve normal JSON numeric types.
- Enforce existing input byte/resource bounds before parsing. Report bounded
  error codes/field paths, never raw output or jsonschema error repr in public logs.
- Reuse the installed jsonschema library against the exact schema generated by
  `_agent_response_schema`, or `_REVIEW_RESPONSE_SCHEMA` for reviewers, including
  required, types, enum and additionalProperties.
  Use validator_for/check_schema with a fixed supported dialect; do not build a
  new schema engine or fetch remote references. Invalid schema is configuration
  failure, not something the model should repair.
- No defaults, coercion, extra-field stripping, guessed arrays, false/zero fill or
  automatic fence/prose extraction. JSON whitespace/key order are not failures.
  JSON Schema alone is not a duplicate-key or nonfinite-number defense.

Schema-valid output is still a model assertion, not proof of business correctness,
file reads, tests, approvals or capability verification.

## One Real Correction

Validate a final no-tool model response inside the Crew gateway bridge before
returning it to the framework. Keep the outer `_execute_step` validation as a
defense, without the field-generating reconciliation fallback.

If role JSON/schema validation fails, allow **at most one correction submission
per logical step per run, shared by worker and independent reviewer**, across
framework re-entry, business retries, model recovery and resume. This is one total
correction, not one per actor or two corrections. Initial worker/reviewer calls
are normal execution, not additional correction allowances. Use the existing configured actor/model/routing policy,
original schema, same private guidance, source evidence and a bounded untrusted
candidate plus deterministic validation errors. Do not introduce a new model
fallback route, restart the step, extend deadlines or reset budgets.

The correction request is format-only and tool-free; a returned tool call is
rejected without execution. Preserve the original tool ledger and completed tool
effects. Tell the model not to invent missing facts: express unknown only where
the existing schema permits it; otherwise leave the step failed. Transport schema
unsupported, auth, cancellation, uncertain outcome and invalid configuration do
not trigger format correction. A second invalid response ends in explicit
structured_output_invalid, never another correction loop.

For structured roles, treat the validated last gateway response as authoritative.
Compare framework raw using the same strict parse and structural/type-preserving
equality (not bool/int-coercing Python equality). Equivalent formatting is allowed
without replacing the provider text. Changed/malformed raw fails with a separate
framework-output mismatch; do not fabricate a GatewayCompletion with its body or
spend another correction to conceal framework rewriting.

## Independent Reviewer Must Fail Closed

An exception, timeout, capacity failure, invalid/missing verdict or exhausted
retry budget is not approve. Emit an explicit review failure/unverified outcome,
retain the candidate as unapproved evidence, and block step/contract completion
and dependent execution. Neither a warning nor skipped/timeout_skipped makes an
approval valid. Failure/partial-result closure must not relabel the candidate as
reviewed or unlock a downstream step.

Approval requires an actual, strictly validated reviewer response from the
configured reviewer, linked to the exact candidate artifact ID/digest and its
request/result ledger evidence. A verified cached result may be reused only for
the matching candidate; a model-written verified flag or a worker claim is not
verification. Preserve real reject/revise outcomes, never coerce them to approve.

The safe first gate is strict rejection. Eligible malformed reviewer JSON may
then receive one real, tool-free reviewer correction if the shared step/run slot
is unused and budget remains. Use the same candidate, reviewer actor, review
schema and evidence, without prompting the model to approve. A worker correction
already using the slot means reviewer failure must stop, and vice versa across
later revisions. reviewer_retries/compact recovery must not hide a second format
or review correction. Cancellation/uncertain outcomes are not repair eligibility.

An existing explicit user-authorized review waiver, if supported, must be checked
against trusted authorization bound to this run/step/candidate and audited as a
waiver, not a successful model review. No new waiver endpoint, implicit opt-out,
prompt-parsed authorization or automatic bypass is introduced here. Without that
authorization or verified approval, do not approve or drive downstream execution.

## Ledger, Budget And Usage

Reuse `_ModelCallCursor`, `_model_call_key`, `_model_request_sha256`,
model_state_boundary, `_complete_with_guidance` and usage_boundary. The correction
gets the next call_index on its actor's existing cursor with purpose=step for a
worker or purpose=review for a reviewer, and its own prepared/running/succeeded
record, request hash, raw response artifact and source lineage. Never
overwrite the invalid original response, provider provenance or ledger entry.

Add bounded checkpoint repair linkage per step (original model key/artifact
digest, correction actor/purpose/key, reviewed candidate ID/digest where applicable,
and reserved/submitted outcome) to make the shared single-submission limit
reconstructible. Reserve under the existing checkpoint synchronization so both
actors cannot claim it. Reserve before the correction call;
validate linkage and artifact graph on restore. Update strict checkpoint schema/
version compatibility explicitly; legacy incomplete checkpoints lacking necessary
repair identity fail closed rather than receiving a fresh allowance.

Replayed succeeded calls cause no new invocation, injected event or usage charge;
running uncertain calls are not reissued. A prepared-but-unsubmitted correction
may use the same reserved key. Changed schema/candidate/guidance must not bypass
request-hash matching. Preserve contiguous cursor and artifact lineage validation.

Record actual usage/cost for worker/reviewer originals and correction responses, even when
schema validation or framework-raw validation fails. Store per-call usage once
through the existing commit path; do not copy the first response's usage onto a
new response or discard failed-format consumption. Missing usage stays explicitly
unaccounted and blocks further paid correction; unknown cost is not known zero.
All calls consume the existing step/run token, cost and wall-time limits. Check
remaining budget before correction and cap output by the remaining allowance.

## Crash / DB-Acknowledgement Limit

Existing model_state_boundary emits checkpoints through a queue. Queue insertion
or an in-memory save_checkpoint result does not prove a committed Postgres write
before the provider call. Reusing that path does not establish DB-acknowledged
write-ahead durability, crash-safe single correction or exactly-once billing.

This slice guarantees the bound for live execution and restoration from a
validated checkpoint that actually contains the ledger/linkage. A crash before
DB persistence can lose that state. Keep this limitation explicit in release
claims. A separate unfinished durability task must add lease-bound DB commit
acknowledgement before side effects and fresh-worker PG crash tests; do not claim
it completed by normal-flow PG, runtime replay or real-provider success.
