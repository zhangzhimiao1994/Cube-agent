# Crew Step Timeout Resilience Design

## Goal

Reduce large-task failures caused by `quality_reviewer_step` or final synthesis timing out, while preserving explicit risk reporting when review cannot finish.

## Current behavior

Crew dispatch builds one step per selected role plus `final_response_step`. Post-product roles such as quality reviewers depend on all producer steps and receive the same `role_step_timeout` as ordinary producer roles. When CrewAI does not return before `step_deadline`, `_complete_agent()` raises `CrewAI step timed out: step=<step_id> actor=<agent_id>`, then `_run_step()` emits `step.failed` and the whole dispatch usually fails.

## Design

1. Step timeout policy becomes role-aware:
   - producer roles keep the current bounded timeout behavior;
   - post-product review/verification/release roles receive a larger bounded timeout;
   - final synthesis receives a larger bounded timeout;
   - large requests and many upstream artifacts raise review/final timeout inside safe caps.

2. Review/synthesis inputs are compacted before being sent to CrewAI:
   - reviewer and final steps receive an `artifact_review_packet` payload per source artifact;
   - packet fields include producer, type, preview, source ids, and stable content keys;
   - the full artifact still remains in source links, but the prompt uses bounded review packets.

3. Reviewer timeout becomes a controlled warning when a candidate artifact already exists:
   - if a configured reviewer times out inside `_review()`, emit `review.completed` with `verdict=approve`, `review_status=timeout_skipped`, warning, step id, actor, and diagnostic fields;
   - continue to checkpoint and final synthesis instead of failing the whole task;
   - high-risk hard-stop policy is left for a later harness/refactor because the current runtime does not yet carry a reliable task-risk contract at step level.

4. Diagnostics classify Crew step timeouts explicitly:
   - `error_stage=crew_step`
   - `error_category=step_timeout`
   - `error_code=crew.step_timeout`
   - include safe `step_id`, `actor`, and `suggested_action`.

## Testing

- Add unit tests for timeout policy generated by `configured_dispatch_plan()`.
- Add failure-diagnostic tests for CrewAI step timeout strings.
- Add Crew adapter tests that reviewer timeout emits skipped review and still completes when the candidate artifact exists.
- Keep existing runtime and frontend diagnostics tests green.

## Non-goals

- No global timeout increase for all roles.
- No new model routing policy.
- No hard dependency on the future harness refactor.
