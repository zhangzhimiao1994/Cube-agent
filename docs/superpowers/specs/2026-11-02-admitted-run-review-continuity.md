# 已准入任务的预算连续性与审查资格

目标：已准入、预算和原截止时间仍有效的在线任务，在自动审查资格仅因时间到期后，仍能完成普通编码及已人工批准的动作。自动审查新动作仍必须持有当前有效资格。

实机依据：9c 部署的一次普通用户 Direct 构建在具体 Python 依赖解析动作处等待审批。该运行持久绑定了 `approval_review_profile`；资格早于原任务截止时间到期。现有 `prepare` 和物理调用检查都会重读过期资格，人工动作审批本身通过也无法保证恢复。旧运行未交付，不计为验收通过。

安全边界：

- 使用新的 v2 准入记录保存可信资格身份与准入时刻。旧 v1 保持原拒绝策略，不改写、补齐或升级历史。
- 连续执行必须使用已存在的原 pool、原授权输入、原 tenant/run/actor、当前受控 worker lease、原 grant、真实剩余余额和不可延长的原截止时间。
- 缺 pool、跨 run、来源不匹配、资格文件被删除或替换、权限撤销、配置或模型目录漂移，继续拒绝；不得以连续性建立新授权。
- 仅资格时间到期与上述撤销条件分开处理。新任务、新预算和每次自动审查仍要求新鲜资格。
- 审查模型在异步等待、物理扣费和发出请求前都验证审查资格，不能只在入口检查。
- 四种模式使用同一边界。普通用户最终得到可安装、可执行、带说明和时间戳的真实交付；失败项必须明确记录。

验收顺序：先复现同一原池的到期恢复问题及拒绝反例，再实现新记录及恢复路径；完成原生隔离验证、部署和普通用户真实构建、独立安装/CLI/文件/UI 核验。旧失败或未知运行不重放，不修改其期限或记录。
