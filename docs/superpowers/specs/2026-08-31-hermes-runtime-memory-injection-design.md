# Hermes+ 运行时记忆取回与注入设计

## 背景

Hermes+ 已经能记录对话学习、调度观察和中文学习摘要，但这些记忆目前主要用于事后查看。要让主 Agent 后续更智能，需要在新任务开始前取回相关的已确认记忆，并把少量高价值内容注入到主 Agent 调度、子 Agent 执行或审查步骤中。

这个能力必须保守实现。错误记忆或噪音如果被自动注入，会直接污染调度判断；所以第一版只允许“已确认、相关、可解释、可回退”的记忆进入运行时上下文。

## 目标

- 运行前从 Hermes+ 取回和当前任务相关的记忆。
- 只注入已确认且通过门控的记忆。
- 支持跨对话模式复用稳定经验，不把“对话模式相同”当作唯一依据。
- 在调度卡片中轻量展示本次是否使用 Hermes+ 记忆。
- 对待确认记忆提供用户确认入口，用户确认后才进入可注入记忆池。
- Hermes+ 检索失败或超时不能阻塞任务执行。

## 非目标

- 不实现完整向量数据库或重型 RAG。
- 第一版不引入 RAG、embedding 或向量索引；避免增加离线部署复杂度、运行延迟和不可解释命中。
- 不把所有历史记忆塞进 prompt。
- 不让 Agent 直接把候选记忆升级为长期有效规则。
- 不在调度卡片主视图堆叠大量确认、降权、删除等管理操作。
- 不处理代码直接修改能力；本项目当前能力边界仍是提供代码修改建议，不能假装具备 harness 级代码执行能力。

## 推荐方案

采用“Agent 预处理 + 用户二次确认 + 运行时门控注入”。

1. Hermes+ 在任务结束后自动提取候选记忆。
2. Agent 对候选记忆做第一轮筛选、归类、去重和中文一句话摘要。
3. 候选记忆进入待确认池，不参与运行时注入。
4. 用户在调度卡片的 Hermes+ 待确认入口中确认、修改或忽略。
5. 只有用户确认后的记忆进入可注入记忆池。
6. 新任务开始时，主 Agent 根据当前任务语义、项目、模块、角色、错误特征和用户指令做取回与门控。
7. 通过门控的 top 3 记忆以短摘要形式注入到对应上下文。

## 记忆判断标准

是否注入不能只看对话模式。不同对话方式中可能有可迁移记忆，相同对话方式中也可能有噪音。

第一版使用以下判断：

- 质量门槛：过滤太泛化、无因果、纯流水账、临时环境状态、未确认、低置信度、重复和过期记忆。
- 当前相关性：按任务语义、项目/模块、错误/成功特征、用户偏好、确认状态和新鲜度评分。
- 可迁移性：用户偏好、项目规则、错误处理原则和 UI 规则可跨模式；单次运行状态和临时环境信息默认不跨模式。
- 冲突判断：如果记忆和当前用户指令冲突，以当前用户指令为准，并把该记忆标记为“检索到但未注入”。

推荐评分口径：

- `score >= 0.65`：允许注入。
- `0.45 <= score < 0.65`：只记录为检索到但未注入。
- `score < 0.45`：忽略。

## 记忆结构扩展

Hermes+ 记忆 payload 增加机器字段，便于解释和门控。

```json
{
  "source_mode": "discuss",
  "applies_to_modes": ["dispatch", "hybrid", "direct"],
  "memory_type": "error_handling",
  "target": "reviewer",
  "confidence": 0.82,
  "noise_risk": 0.18,
  "injection_reason": "命中 reviewer 超时处理经验"
}
```

字段含义：

- `source_mode`：记忆来源的对话/执行模式。
- `applies_to_modes`：允许复用到哪些模式；为空时按默认迁移规则判断。
- `memory_type`：用户偏好、项目事实、UI 规则、错误处理、调度规则等。
- `target`：注入目标，例如 main_agent、scheduler、reviewer、frontend、hermes。
- `confidence`：系统判断该记忆稳定有效的置信度。
- `noise_risk`：系统判断该记忆可能是噪音的风险。
- `injection_reason`：本次为什么注入或为什么建议确认。

## 注入位置

不同记忆注入到不同上下文，避免污染主 Agent prompt。

| 记忆类型 | 注入位置 |
|---|---|
| 用户偏好 | 主 Agent 行为约束 |
| 项目事实 | 任务上下文 |
| 调度经验 | 调度器上下文 |
| 子 Agent 失败教训 | 对应子 Agent 执行提示 |
| reviewer 超时经验 | 审查步骤配置或 fallback 策略 |
| 对话总结 | 背景摘要，不直接改变执行计划 |

第一版每次最多注入 3 条，每条控制在 120-200 字，总注入文本控制在约 800 字以内。

第一版取回方式使用结构化字段、标签匹配和规则评分。后续即使增加向量检索，也只能作为候选召回层，不能直接决定注入。

## 待确认交互

调度卡片主视图只显示轻量入口，不放完整记忆列表。

示例：

```text
Hermes+ 记忆：待确认 3 条
```

这整行作为可点击区域，不额外显示“查看详情”按钮。

点击后打开详情抽屉，桌面端使用右侧抽屉，移动端使用底部抽屉。抽屉中展示：

- 本次候选记忆数量。
- 建议确认、建议忽略数量。
- 每条记忆的中文一句话摘要。
- 类型、作用范围、建议动作。
- 操作：确认、修改、忽略。

关闭规则：

- 点击遮罩区域关闭抽屉。
- 不增加 Esc 关闭能力。
- 不允许遮罩背后的原页面继续滚动。
- 关闭后调度卡片中的待确认数量需要实时更新。

## 调度卡片展示规则

主卡片只显示结果摘要。

```text
本次调度：自动模式 → 拆分执行
子 Agent：3 个
Hermes+：注入 2 条记忆
风险：1 个超时风险，已启用重试策略
状态：执行中
```

复杂内容进入抽屉：

- 注入了哪条记忆。
- 为什么注入。
- 为什么某条记忆未注入。
- 哪些记忆待确认。
- 子 Agent 完整输出。
- reviewer 重试和降级细节。

## 错误处理

- Hermes+ 检索超时：记录 `memory_retrieval_timeout`，任务继续执行。
- Hermes+ 记忆解析失败：跳过该条记忆，其他记忆继续参与评分。
- 注入内容超限：按分数截断，只保留最高分。
- 用户当前指令覆盖记忆：不注入，并记录覆盖原因。
- 待确认接口失败：保留调度卡片入口，提示用户稍后处理，不阻塞主任务。

## 测试计划

- 后端单元测试：未确认记忆不会注入。
- 后端单元测试：不同模式但高相关的项目规则/错误处理记忆可以注入。
- 后端单元测试：相同模式但低质量或临时状态记忆不会注入。
- 后端单元测试：当前用户指令覆盖旧记忆时不注入。
- 后端单元测试：Hermes+ 检索失败或超时时任务继续提交。
- 前端测试：调度卡片只显示 Hermes+ 摘要入口。
- 前端测试：点击待确认入口打开抽屉。
- 前端测试：点击遮罩关闭抽屉。
- 前端测试：不依赖 Esc 关闭抽屉。
- 前端测试：抽屉打开时外层页面不可滚动。
- 集成测试：任务提交后 routing decision 中记录注入/未注入的 Hermes+ 解释信息。

## 后续改进

第一版完成后，再逐步增强：

1. 注入效果反馈：记录每条记忆被使用后的任务结果。
2. 自动降权：连续导致错误判断的记忆进入复核或降权。
3. sleep 增强：离线去重、合并、冲突检测和权重调整。
4. Agent/模型级个性化：记录不同 Agent 和模型的稳定能力差异。
5. 注入预览与撤销：任务开始前允许用户撤销某条将被注入的记忆。
